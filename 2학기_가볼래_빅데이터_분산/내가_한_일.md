## 문제와 선택

### 1. 10초 넘게 걸리는 추천을 어떻게 기다리게 할까

**상황**
여행 일정 추천은 후보 장소를 고르고 하루마다 경로를 최적화해서 길게는 10초를 넘겼습니다. 요청 하나로 끝까지 기다리면 그사이 연결이 끊기거나 사용자가 화면을 떠납니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 요청 하나로 끝까지 기다린다 | 구현이 가장 단순 | 타임아웃·끊김에 약하고 진행 상황을 못 보여 준다 |
| B. 작업 번호를 먼저 받고 **폴링**으로 진행 확인 | 어디서나 동작 | 요청이 많고 반응이 늦다 |
| C. 작업 번호를 먼저 받고 **SSE**로 진행을 받는다 | 즉시 반영, 요청이 적다 | React Native의 `fetch`는 응답을 조금씩 읽지 못한다 |

**선택: B와 C를 함께**
서버가 작업 번호를 먼저 돌려주게 하고, **웹은 SSE, 앱은 2초 폴링**으로 나눴습니다. 웹에서 SSE가 끊기면 조용히 폴링으로 갈아탑니다. 두 경로가 따로 상태를 해석하면 한쪽만 고쳐지는 날이 오기 때문에, 응답 모양을 맞춰 **판단 함수 하나**로 모았습니다.

**결과**
진행률이 뒤로 가지 않게 하는 규칙과 실패 문구가 두 경로에 똑같이 적용됐습니다. 네트워크가 한 번 끊겼다고 실패로 끝내지 않고, "응답 없음"과 "거절"을 구분해 다시 시도합니다.

### 2. 요청 열 개가 동시에 401을 받으면 로그아웃된다

**상황**
홈 화면을 열면 API 요청이 여러 개 동시에 나갑니다. 접근 토큰이 막 만료됐다면 전부 401을 받고, 각자 갱신을 시도합니다. 서버는 갱신 토큰을 쓸 때마다 새것으로 바꾸기(회전) 때문에, **두 번째 갱신 요청은 옛 토큰이라 거절되고 사용자가 로그아웃**됐습니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 서버의 토큰 회전을 끈다 | 프론트 수정 없음 | 토큰을 훔친 사람을 알아챌 수단이 사라진다 |
| B. 요청을 하나씩 순서대로 보낸다 | 충돌이 없다 | 화면이 느려진다 |
| **C. 진행 중인 갱신 Promise를 공유한다(single-flight)** | 갱신은 한 번, 나머지는 그 결과를 같이 기다린다 | 갱신 실패 시 처리 규칙을 따로 정해야 한다 |

**선택: C**
첫 401이 갱신을 시작하면 뒤따른 401은 같은 Promise를 기다리게 했습니다. 갱신 후 다시 보낸 요청이 또 401이면 무한 반복하지 않고 멈추고, **통신 실패는 로그아웃 사유로 보지 않게** 했습니다. 로그인 뒤 원래 화면으로 돌려보낼 때는 `//다른사이트` 같은 주소를 막았습니다.

**결과**
동시 요청 상황에서 로그아웃되는 문제가 사라졌습니다. 이 경험은 이후 자율 프로젝트에서 로그인 서비스를 직접 만들 때 갱신 토큰 회전·재사용 감지 설계의 바탕이 됐습니다.

### 3. 일본어 화면에서 문구 208곳이 조용히 영어로 나왔다

**상황**
앱은 한국어 원문을 그대로 번역 열쇠로 쓰는 방식(`tx(ko, en)`, 호출부 1,500곳 이상)이었습니다. 그런데 `사진 2/3`처럼 **숫자가 낀 문구는 실행할 때마다 원문이 바뀌어** 번역표에서 영원히 찾지 못했고, 일본어·중국어 화면에서 영어로 떨어졌습니다. 한국어로만 앱을 보는 개발자에게는 보이지 않는 버그였습니다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 208곳 호출부를 하나씩 고친다 | 확실하다 | 시간이 오래 걸리고, 새로 생기는 자리는 또 놓친다 |
| B. `"plan.photo_count"` 같은 키 방식으로 전부 바꾼다 | 업계 표준 | 1,500곳을 모두 고쳐야 한다 |
| **C. 숫자를 빼고 "모양"으로 한 번 더 찾는다** | 찾는 함수 하나만 고친다 | 이름처럼 글자가 끼는 문구는 못 고친다 |

**선택: C**
`사진 2/3`에서 숫자를 빼면 `사진 %d/%d`가 됩니다. 원문 그대로의 번역이 있으면 그것을 먼저 쓰고, 없을 때만 모양으로 찾아 숫자를 다시 채우게 했습니다. 이름이 끼는 자리는 별도 함수(`txf`)를 쓰도록 규칙을 정했습니다.

**결과**
208곳을 호출부 수정 없이 해결했습니다. 번역 누락은 CI 검사(`npm run verify`)에 넣어 새로 생기는 자리도 막았습니다.

## 돌아보며

- 화면 하나를 고칠 때도 **같은 원인을 가진 다른 화면**을 먼저 찾았습니다. 버튼이 글자 폭으로 쪼그라드는 문제는 한 화면에서 발견했지만, 같은 원인을 가진 로그인 뒤·실패 상태 화면 10여 곳을 함께 고쳤습니다.
- 출시 직전에는 5개 언어 × 폴드·태블릿 조합을 전부 돌려 보며 낱말 중간 꺾임, 한 글자 폭으로 짓눌리는 화면을 잡았습니다.
